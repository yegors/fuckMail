Historical synthetic profiles retain their fixture revision and authored/source/receipt data.

Live creation intent is persisted before opening SQLite, and profile kind commits with the initial schema before seeding or later migrations. A failed first transaction or interrupted migration therefore cannot reopen as a demo; an incomplete intent marker is refused. Existing profiles open according to their stored kind; explicitly requesting a different kind fails without conversion. Migration creates an opaque persistent profile namespace for vault isolation and account bindings keyed by immutable Google subject. Only the engine's verified-auth path can register a binding; no raw IPC account/subject registration method is exposed. Reconnect must match the original subject. Email remains mutable metadata. Grants, connection state and coverage are local metadata; tokens never enter SQLite or protocol responses.

Before adapter wiring, live capabilities remain false and synthetic capture/calendar acknowledgments are refused on live profiles. Ordinary queries cannot launch OAuth or invent synced/completed coverage. No real data is imported in this packet: actual destination permissions, encryption and remaining retention/backup inputs are separate admission checks.

Pass evidence will include fresh live profile/reopen with zero accounts/messages/calendar/drafts/operations/blobs, interrupted initialization without seeding, immutable profile kind, namespace separation, account deduplication and reconnect mismatch refusal, partial grant capabilities, disconnected retained work, synthetic-operation refusal, and schema-7 migration preserving fixture/source/authored/receipt data.
