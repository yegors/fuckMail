## Implemented boundary

`fm_google::transport` exports `HttpTransport::execute(HttpRequest, &CancellationToken)` as a boxed Send future, `ReqwestTransport`, `HttpMethod`, `HttpResponse`, `TransportLimits` and sanitized `TransportError`. The request builder accepts fixed Google HTTPS hosts/routes, disallows URL credentials/token query parameters and limits request headers to the API/auth/precondition inventory. Production disables redirects, ambient proxies, cookie/compression features, referrers and reqwest's internal retries. Conditional GET 304 remains an ordinary response. Request/response Debug omit URLs, headers, bodies and ETags. Error values never include reqwest/provider text.

Defaults are a 10-second connection deadline, 30-second read deadline and 120-second whole operation deadline, with a 64 MiB request/response ceiling. Adapters tighten the response limit (OAuth uses 64 KiB, JWKS 256 KiB); explicit limits permit at most 128 MiB. Size/deadline failures never return a partial body as complete. The adapter buffers within its ceiling; streaming large RAW/blob acquisition is a separate P2-03 consumer decision. Cancellation drops the request/body future; it does not prove a submitted mutation was rejected remotely.

`fm_google::scheduler` exports `SchedulerConfig`, `ServiceBudget`, `Scheduler`, `Work`, `WorkId`, `WorkClass`, `Permit`, `CooldownScope` and `retry_delay`. A worker registers account IDs, enqueues costed work, drains `next(monotonic_ms)`, executes each permit once and always calls `finish` on success/error/cancel. It waits on completion/new work plus `next_wake_ms` for a quota/cooldown timer; the scheduler creates no thread, timer or network request. Every batch subrequest must be included in `Work.units` by its typed API adapter. `ServiceBudget::from_confirmed_limits` applies conservative 80% headroom to actual Console limits; no project quota is invented by a default.

Gmail/Calendar project and account budgets use rolling 60-second charges, retained after failure/cancel. Rotating account/service queues admit at most four urgent reads/deltas/writes before preferring an eligible backfill, preserve FIFO account mutation order across services and serialize mutations per account (therefore per calendar too). Defaults allow two concurrent reads/account and four operations overall. Backfill cannot consume the last quarter of concurrency or more than three quarters of either budget. Fairness is conditional on quota availability; an exhausted budget or cooldown can legitimately prevent backfill. Queues/accounts are bounded. Read retry recommendations stop after six attempts, honor Retry-After and reject terminal errors; all mutation classes receive no generic retry recommendation.

The initial compiler run found an OAuth serializer held across await; its owner corrected that before successful tests. The first Clippy run found one collapsible callback Host check; its owner corrected it. Those findings affected the adjacent concurrently implemented auth code, not a live account.

The new dependencies resolve with pinned Rust 1.88 on the available Windows development host. Native-root TLS client construction is exercised, but trusted server/certificate rejection, SDK-free package root discovery, other native hosts, worker shutdown/UI latency and actual Google quotas are still integrated acceptance gates. No Google endpoint or real credential was used for these tests. The transport/scheduler is an implemented slice, not a complete P2-02 or Google-first readiness pass.

## Explicit Windows native-root HTTPS probe, 2026-09-13 UTC

The ignored `transport::tests::native_roots_public_google_jwks_smoke` was explicitly run **once** through production `ReqwestTransport` against Google's fixed public [JWKS endpoint](https://www.googleapis.com/oauth2/v3/certs). It passed: **HTTP 200, valid key-set JSON with 2 usable verification keys, 103 ms**. The request supplied no bearer, account or other credentials. Redirects and retries remained disabled; limits were 5 seconds connect/read, 15 seconds total and 256 KiB response. Logs retain only status, validation/count and elapsed time—no key body. [Sanitized execution log](assets/phase-2/p2-02/native-roots-public-jwks-windows.log).

This proves native-root HTTPS execution on the current Windows development host for public identity metadata. It does not verify a Google account, OAuth grant, mailbox, package root discovery or another host. The probe stays ignored in ordinary credential-free/native CI. Unknown-certificate rejection was **not exercised**; no certificate was installed into native trust and no rejection fixture is claimed.
